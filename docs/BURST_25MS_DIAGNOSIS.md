# 25 ms 内重复输出排查（2026-10-23）

最新实测回读：`00=0000, 1E=0000, 1F=0001, 2A=0000, 2B=0000, 28=0515, 29=3A02, 44=0000, 45=0000, 60=0000`，用户确认仍有波形串。影子配置正确及任务结束后 RUN=0 不能证明触发瞬间有效配置已正确提交。

已查明并修正一处手册时序违例：上一版本上电、COMMIT、RETRIGGER 是 `RAMUPDATE → RUN=1 → TRIGGER`；手册第 31 页步骤和 ADI 技术支持要求 `RUN=1 → RAMUPDATE → TRIGGER`。见 [修正后的启动顺序及来源](AD9106_SINGLE_PATTERN.md)。测试新增独立于 PC 写入列表的 SPI 监视器，检查上电、首次发送和再次触发时的最后两笔写入；停止路径保持 `RUN=0 → RAMUPDATE`。尚需板上测量判断该修正是否消除整个 25 ms 波形串。

补充实测：用户确认芯片 Pin 32 低电平约 20 µs，在第一枚脉冲下降前下降；不能确认是否恰好重复 256 次，也不能确认本次烧录文件。因此继续排查芯片配置实际写入情况，新增 [SDO 寄存器回读](REGISTER_READBACK.md)。以下原有仿真结论仍不能证明模拟输出正常。

板上反馈：约 1 秒触发一次，但每次输出约 25 ms、约 250 个 100 µs 周期。尚未定位根因，以下为项目侧已核对结果，不能代替芯片回读或实测。

最近保存的 `.uart_sim/firing_web_plan/plan.json`：DAC3 静态 Vin，100 µs 单元，10–20 µs 脉冲。DAC3 SRAM 共 2970 点、HOLD=5，只有一次从零进入正脉冲的跳变。`PAT_TYPE=1`，`0x2A/0x2B=0`，`PAT_TIMEBASE=0x0515`，`PAT_PERIOD=0x3A02`。FPGA 截止计数为 2110 个 100 MHz 时钟，TRIGGER 低电平持续 21.1 µs。

`RUNTIME_STOP_CYCLES=2000000` 的 20 ms 等待发生在首次停止写入之后，此时 TRIGGER 已拉高；它不用于维持 TRIGGER 低电平。截止时 FPGA 发出 RUN=0，1 MHz SPI 每笔 32 位写入约需 32 µs，然后发出 RAMUPDATE。源码中没有设置 25 ms 输出窗口或 250 次重复。

重新运行 `tools/test_firing_uart.ps1 -Top -Scene .uart_sim/firing_scene.json`：450 个 PC 帧、3022 笔编程 SPI 写入逐笔比对通过；第一次及再次触发的低电平宽度检查、截止后的 RUN=0/RAMUPDATE 顺序检查通过。此测试没有芯片模拟输出模型，也未通过 SDO 回读实物。

下一步所需实测：同时观察 Pin 32 和 Vin，确认此次 TRIGGER 低电平宽度及其相对波形串的位置。若低电平约 21.1 µs 而 Vin 持续 25 ms，应抓取芯片脚上的 CS/SCLK/SDIO，核对 `001F0001`、`002A0000`、`002B0000` 及截止后的 `001E0000`，并回读芯片配置。若低电平本身约 25 ms，应先核对板上 bitstream、时钟和 FPGA 截止计数。100 µs × 256 = 25.6 ms 只是需要验证的线索，不能据此断定芯片计数器溢出或将手册规定的单次计数从 0 改为 1。
