# 实物寄存器回读诊断

烧录包含回读功能的新 bitstream，重新启动 `tools/start_firing_gui.cmd` 并刷新浏览器。先检测串口；完成一次播放任务后，点击“回读芯片寄存器”，把日志中的整行读值保留。该操作不会发送 TRIGGER 或修改芯片寄存器。命令行等价操作：`python tools/ad9106_diagnostics.py --port COM3`（替换实际串口）。

关注 `0x1F=0x0001`、`0x2A=0x0000`、`0x2B=0x0000`。当前简化版本播放结束后 `0x1E[0]` 保持 1（不再自动清 RUN）；`0x1E[1]` 是芯片 PATTERN 状态。当前静态场景的 `0x28=0x0515`、`0x29=0x3A02`。也读取 `0x00`、`0x44`、`0x45`、`0x60`，用于排查接口配置和错误标志。若所有值均为 0 或 FFFF，先检查 SDO 连线：芯片 Pin 7 → R5 → H2.4 → FPGA E16。

按 AD9106 Rev.C 手册，配置回读反映影子寄存器，不能单独证明有效寄存器或模拟输出正常。当前“20 µs 触发、约 25 ms 波形串”的根因尚未确认，不应将回读功能视为已修复该现象。

UART 请求沿用 24 字节格式，CMD=`45`，负载前两字节为大端寄存器地址（0000–0060），其余负载补零。回复为 10 字节：`55 AA SEQ 45 STATUS DATA_H DATA_L XOR 0D 0A`，XOR 覆盖 SEQ 至 DATA_L。其他命令仍回复 8 字节。旧固件返回 unknown command，PC 会明确提示更新固件。

验证覆盖 SDO 返回 0001、0000、A55A、FFFF、UART 数据顺序与校验、非法地址拒绝，以及回读期间没有配置写入或额外触发。仿真芯片模型只用于验证数字接口。

当前版本额外读取 0x26/0x27（波形来源）和四路 START_DELAY、START_ADDR、STOP_ADDR，以核对实际 SRAM 地址段。回读本身不改变 TRIGGER/RUN。完整流程见 [芯片单次播放](AD9106_SINGLE_PATTERN.md)。
